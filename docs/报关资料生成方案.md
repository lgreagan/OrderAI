# 出口报关资料（货代 xlsx 模板）生成方案 —— 品类 / 申报要素 / 模板适配

> 目标：对 `excel/templates/` 下的两份**货代报关资料模板**（`DE-海运.xlsx`、`UK--海运.xlsx`），实现「业务员选模板 → 系统按品类装配数据 → 一键生成**样式与模板完全一致**的 Excel」，模板上不变的信息（货代抬头、标签、下拉、辅助表、字体边框、列宽行高、合并单元格）全部保留，**系统里没有的数据一律留空**，由业务员在 Excel 里补填。
>
> **模板以 `.xlsx` 形式由业务员自备并放到 `excel/templates/`，系统不做 `.xls` 解析与格式转换**（见 §4.2、§10 决策 4）。
>
> 与 `docs/PI生成方案.md` 同源：同样走「excelize 开模板 → 克隆样式 → 只写值」的路线，同样遵守留空策略。

---

## 1. 目标与范围

| 项 | 内容 |
| --- | --- |
| 输入 | 货代提供的报关模板 **`.xlsx`**，由业务员自备并放在 `excel/templates/`（当前两份：`DE-海运.xlsx`、`UK--海运.xlsx`） |
| 输出 | `.xlsx`（已确认货代接受 xlsx，服务端零依赖、纯 Go 生成） |
| 数据粒度 | 明细**按发货明细逐行**出行（一条发货明细 = 一行）；品名/材质/HS/用途/申报单价取 SKU 挂的报关品类 |
| 入口 | 发货单详情页 →「生成报关资料」→ 下拉选模板 → 预览/微调 → 下载 |
| 不在范围 | 不改动货代模板的业务含义、不代填 VAT/EORI 等系统内不存在的数据 |
| 不在范围 | **系统不解析、不转换 `.xls`**：模板的 `.xls → .xlsx` 转换在系统外由业务员用 Excel 完成（见 §4.2） |

## 2. 两份模板的严格解读

> 解析方式：原始 `.xls` 用 `xlrd` 逐单元格读取（值/合并/行高/列宽/xf），随后由业务员用 Excel「另存为 `.xlsx`」放到 `excel/templates/`，再用 `openpyxl` 复核（公式、数据验证、图片、样式）。**运行期系统只认 `.xlsx`。**
> 实测结论：**两份模板均无公式、无嵌入图片**；DE 无数据验证，UK 有 7 组下拉。

## 3. 生成规则与留空策略

### 3.1 明细行 = 一个报关**品类**

```
发货单
 └─ 明细行（shipment_items，按 SKU）
      ├─ 数量 / 箱数 / 货箱编号 / 重量 / 箱规  ← 取本条明细自身
      └─ SKU.product_category_id → 报关品类(product_categories)
             └─ 品名 / 材质 / HS / 用途 / 品牌 / 型号 / 链接 / 默认申报单价
                              ↓
                    报关明细 1 行 / 发货明细（2026-10-17 起）
```

| 明细列 | 取值 |
| --- | --- |
| 产品英文品名 / 产品中文品名 / 材质 / 海关编码 / 用途 / 品牌 / 产品销售链接 | **品类表**（`product_categories`） |
| 产品型号 | 品类 `model`；品类没填（空或「无」）时用本条明细规格 `shipment_items.short_name` |
| 产品申报单价 / 申报单价 | `skus.declare_price`（SKU 自己的申报价）→ 品类 `declare_price` → 明细成交单价 → `skus.price_usd` |
| 产品销售价格（仅 DE） | 本条明细成交单价 `shipment_items.unit_price` |
| 产品申报数量 / 单箱申报数量 | 本条明细数量、`数量 / 明细箱数` |
| 申报总价 | `申报单价 × 本条明细数量` |
| 货箱编号 | 本条明细 `carton_no`（多段连号合并为区间） |
| 货箱重量 / 长 / 宽 / 高 | 明细值，缺省回落 `skus.box_weight` / `box_length/width/height` |
| 产品图片 | `skus.image`（本条明细的 SKU），无图写 `无` |
| 产品 ASIN / FNSKU / SKU（仅 DE） | 本条明细 SKU 自己的 `skus.asin` / `skus.fnsku` / `skus.sku_code` |
| PO Number（仅 UK 明细列 B） | 明细 `po_number` |

### 3.2 抬头取值

| 抬头 | 来源 |
| --- | --- |
| 客户订单号 | `orders.order_number` |
| 服务（渠道）/ 运输方式 | `shipments.shipping_method`（与 `shipping_channels` 对齐，保证下拉可命中） |
| 地址库编码 + 收件人信息 | `shipments.warehouse_code` → `warehouse_addresses` 带出；带不出时**保持模板原样**并给出提醒 |
| 收件人地址一（多行） | `declare_extra`（报关附注，如 `Anmelder: POLZEN LTD` 整段）+ 地址一/二/三 按行拼接 |
| 箱数 | `Σ 明细箱数` |
| 带电/带磁/液体/粉末/危险品/购买保险 | `shipments` 的商品属性标记，仅**勾选时写「是」**，未勾选沿用模板默认「否」 |
| 报关方式/交税方式/申报币种 | `shipments.customs_mode` / `tax_mode` / `declare_currency` |
| 备注 | **不写**（发货单备注是内部运营文字，不落进报关件） |

### 3.3 留空策略（与 PI 方案一致）

| 区块 | 处理 |
| --- | --- |
| 货代抬头、所有标签、下拉、`仓库地址`/`渠道` 辅助表 | **原样保留**，绝不改写 |
| VAT号 / EORI / VAT注册国家 / 公司英文名 / 注册地址 / 参考号 / 邮箱 / 交货条款 | **留空**（系统无此数据） |
| 产品图片 / 品牌 / 型号 | 缺省写「无」 |
| 模板自带默认值（如 UK `F7=买单报关`、`F8=包税`、`F9=美元`） | 系统有值时覆盖，无值时**沿用模板默认** |
| 模板自带样例行 | 只清值 + 超链接 + 样例产品图，**样式与下拉不动** |
| 明细行数不足/超出样例行数 | 不足则清空多余样例；超出则 `InsertRows` 并克隆母版行的列样式与行高 |

### 3.4 数量 / 金额格式（沿用样例）

| 字段 | DE | UK |
| --- | --- | --- |
| 申报数量 | 文本 `{总数}({每箱数}/箱，{箱数}箱）` | `单箱申报数量` 数值 + `申报总价` 数值 |
| 币种后缀 | 无 | 系统设置决定是否加 `USD` 后缀（默认不加，与样例多数行一致） |

## 4. 技术路线

### 4.1 为什么不是「直接改 .xls」

| 方案 | 结论 |
| --- | --- |
| Go 库直接写带样式的 `.xls` | ❌ 生态内没有（`extrame/xls`、`shakinm/xlsReader` 均**只读**） |
| 二进制 patch BIFF 流 | ❌ 无 SST/样式管理，脆弱不可维护 |
| 运行时 Excel COM / LibreOffice | ❌ 服务端引入 Office 依赖 |
| **系统外一次性转 `xlsx` + 服务端 `excelize` 填值** | ✅ **采用**（已确认货代接受 xlsx） |

### 4.2 模板准备（业务员自备 xlsx，系统不参与）

```
excel/DE-海运.xls   ──业务员 Excel 另存──>  excel/templates/DE-海运.xlsx
excel/UK--海运.xls  ──业务员 Excel 另存──>  excel/templates/UK--海运.xlsx
```

**这一步不在系统内**：系统只从 `excel/templates/` 读取 `.xlsx`，不做 `.xls` 解析、不做格式转换、也不需要服务端安装 Excel/LibreOffice。

模板验收项（已实测通过）：合并单元格 **DE 48 / UK 32** 个全保留；UK **7 组数据验证**全保留；`仓库地址`(592 行) / `渠道`(75 条) 两张辅助表全保留；列宽、行高、微软雅黑字体、细边框、`wrapText` 全保留；**无公式**；模板自带的样例产品图（DE 12 处 / UK 16 处锚点）与 11 条超链接在导出时清除，货代抬头图（UK `B2:O16` 与 `A1`）保留。

> 转换方式二选一：① 本机 Excel「另存为」（已验证）；② LibreOffice `--convert-to xlsx`。新增模板由业务员自己转好 `.xlsx` 放进 `excel/templates/`，系统只负责「下拉选模板 → 按映射写值 → 导出」。

### 4.4 生成（`DeclarationExcelService`，对标 `PiExcelService`）

```

4. captureDetailStyles()                     // 以 firstDataRow 为样式母版，逐列 GetCellStyle
5. resetTemplateBody()                       // 清除 sampleRows 的值 + 超链接，保留样式
6. writeHeader()                             // 按 mapping.header 写抬头
7. writeDetailRows()                         // 逐品类写入；
                                             //   行数 > 母版行数 → f.InsertRows 后 CopyStyle 克隆母版行
                                             //   < 母版行数 → 多余母版行清空

9. WriteToBuffer() → 返回 []byte
```

## 6. 关键流程

### 6.1 模板准备与登记

```
业务员：货代 .xls ──[系统外] Excel 另存──> excel/templates/<name>.xlsx
                                             │
                                             └─> 在 declaration_templates 登记一条（下拉即由此而来）
                                                   │
                                                   └─ 映射：优先套用同 country 的既有映射；新结构由管理员在
                                                      「模板管理」页按 §4.3 填写（单元格地址 + 明细列字母）
```

> 系统不接收 `.xls` 上传、不做转换；`excel/templates/` 里放什么由业务员决定，登记表决定「下拉里出现哪些模板、各自映射到什么格子」。

### 6.2 报关行装配（一条发货明细 = 一行）

> 2026-10-17 变更：原按「报关品类」聚合出行，现改为**按发货明细逐行**出行——海关要能逐箱看清装的是什么产品。
> 品类不再决定行数，只提供申报要素（品名/材质/海关编码/用途/品牌/链接/申报单价）。

```
1. 取发货单 + 明细(shipment_items) + 明细关联 SKU
2. SKU.product_category_id → product_categories；未挂品类的明细行标黄提示（汇总一条 warning）
3. 每条明细出一行：数量/箱数/货箱编号/重量/箱规取本条明细自身（箱数缺失时按整箱数量 ceil 折算）
4. 申报要素取品类；品类「型号」为空或「无」时，用本条明细规格（short_name）补位，便于区分同 HS 不同规格
5. 申报单价优先级：`skus.declare_price`（SKU 自己的申报价）→ 品类 `declare_price` → 明细成交单价 → `skus.price_usd`；销售价格取本条明细成交单价
6. 抬头：订单号 / 运输方式 / 地址库编码 → warehouse_addresses 带出收件人
7. 输出预览表（可手工改数量、箱数、箱号）
```

同一 SKU 若在发货单上分成多条明细（不同批次/箱号），报关也保留多条，不再合并。

### 6.3 Excel 写入要点

| 要点 | 做法 |
| --- | --- |
| 清样例行 | 清值 + 清超链接，**保留样式**（`sampleRows`） |
| 行数不足/超出 | `f.InsertRows` 后 `f.SetCellStyle(..., f.GetCellStyle(母版列单元格))` 逐列克隆母版样式 |
| 合并单元格 | 抬头区值列写入**左上角**（`B`/`F`/`J`），其余不动 |
| 辅助表 | 一律不触碰（保下拉可用） |
| 图片 | `f.AddPicture`，按行高等比缩放、居中；图片文件不存在时写「无」 |
| 数字列 | `gross_weight/length/width/height/declare_price` 写**数值**（不写文本），保证可计算 |

### 6.4 数量 / 金额格式

| 字段 | 规则 |
| --- | --- |
| DE `产品申报数量` | `fmt("%g(%g/箱，%g箱）", 总数, 每箱数, 箱数)` |
| UK `单箱申报数量` / `申报总价` | 数值；`申报总价 = 单价 × 单箱数量 × 箱数` |

| 1 | **输出格式** | ✅ **`.xlsx`**（货代接受；服务端零依赖、纯 Go 生成，不需要 Excel/LibreOffice） |

## 12. 怎么用（本版落地后的操作步骤）

1. **建报关品类**：左侧导航「报关品类」→ 新增，填 英文品名 / 中文品名 / 材质 / 海关编码 / 用途 / 品牌 / 型号 / 产品链接 / 默认申报单价。
   *预置数据见 §12 表格：现行口径是「同一海关编码合并为一个品类」，`CAT-DOG-TREAT-BALL` 一条覆盖 6/7/8cm、V2 各色全部西瓜球/专利球；新增同 HS 规格时不要再单独建品类，直接挂这一条。*
2. **给 SKU 挂品类 + 填申报单价**：「产品管理」→ 编辑 SKU → 「报关品类」下拉；同品类下不同规格价格不同时，在 **「申报单价（USD）」** 各填各的（留 0 就沿用品类默认价）；DE 模板还要填「产品 ASIN / 产品 FNSKU」（报关时逐行带出）。
   *14 个 SKU 已按 `product_name` 挂好（`sql/seed_sku_product_category.sql`），新增 SKU 时按同样规则选品类即可。*
3. **发货单填报关信息**：「发货管理」→ 编辑发货单 → 「报关资料（生成货代模板用）」区域填
   `地址库编码`（如 `BHX4`，会带出收件人）/ `PO Number` / `报关方式` / `交税方式` / `申报币种` / 危险品标记 / 报关模板；
   明细表最后一列填 `货箱编号/FBA`（如 `FBA15MHZN8KKU000001-7`）。
4. **生成**：「发货管理」列表行 →「报关资料」→ 选模板 → 预览（可改数量/箱数/货箱编号）→「下载报关资料」；下载完成会自动留档，「历史导出记录」里可查看每次导出的快照。
5. **维护收件人 / 报关附注**：「报关模板」→ 仓库地址库 →「新增」或「编辑」，`报关附注` 填 `Anmelder:/Declarant:` 整段多行文本；发货单填了对应「地址库编码」时会自动拼到收件人地址一的最前面。
6. **新增货代模板**：自己把货代的 `.xls` 用 Excel「另存为 `.xlsx`」放到 `excel/templates/`（**这步系统不做**），然后按 §4.3 改一份映射 JSON 登记进 `declaration_templates`（也可在「报关模板」页改），**无需改代码**。下拉里出现的就是 `declaration_templates` 里登记且启用的模板。
