# 2026-10-15

## 生产 / 库存模块链路审查（未改代码）

审查范围：采购到货 → 生产领料 → 完工入库 → 发货出库 的库存记账链路。

### 当前记账链路（代码事实）
| 环节 | 触发点 | 库存流水 |
|---|---|---|
| 采购到货 | `PurchaseOrderService.Receive` | SKU/材料 +N，biz=purchase_in |
| 生产领料 | `InventoryService.IssueMaterials`（领料页手工） | 材料 −N，biz=requisition |
| 完工登记 | `ProductionOrderService.Complete` | SKU +N，仅当 `SourcePurchaseOrderID == nil` |
| 发货 | `ShipmentService.Save` → `syncInventory` | SKU −N，仅当状态=shipped/delivered |

### 确认存在的问题
1. **重复入库未根治**：跳过入库的判断依据是 `source_purchase_order_id` 字段。
   从客户订单下推的生产单（`PushDown`）或手工新建的生产单（不带来源）仍会完工入库。
   若同一 SKU 既走了采购到货入库、又走了订单下推生产 → 成品记两次。
   两条下推路径互不感知，系统不校验"该 SKU 是否已采购入库"。
2. **发货不扣任何材料**：`syncInventory` 只有 SKU 出库分支，无材料分支。
   包装用料（纸箱）唯一出口是领料页手工操作，漏点即长期挂账。
3. **到货即发货的货被塞进"生产"**：靠"采购单下推生产单"实现，语义错误；
   该场景库存上只应消耗包装材料，不应有任何成品进出。
4. **记账口径不统一**：`Complete`/`Receive` 是增量累加（改数量写 adjust 流水，留噪音、无幂等）；
   `syncInventory` 是先删后重算。建议统一为重算式。
5. **采购单编辑删行不冲销入库流水**：`PurchaseOrderRepository.Update` 全删重建明细，
   `received_quantity` 仅在行 ID 匹配 `preserveReceived` 时保留；行被删则归零，
   但 `inventory_transactions` 里对应 purchase_in 流水仍存在 → 单据未到货、库存已增加。
6. **生产单删除连带删除领料流水**：`ProductionOrderService.Delete` 调
   `DeleteByRef("production_order", id)`，会抹掉已实际消耗的领料出库记录 → 材料库存凭空回涨。

### 建议改造方案（待用户确认后实施）
核心：把"该不该动库存"变为生产单上的**显式字段** `work_type`，替代隐式的来源推断。
- `produce` 投料生产：领原料 −，完工成品 +
- `pack` 包装装箱：只领包装材料 −，成品不动
- `none` 只记录：无库存变动
由来源自动推断（采购下推→pack，订单下推→produce），允许人工修改。
配套：完工入库改重算；发货按 BOM 自动核销包装材料（可开关）；
采购单编辑时冲销消失行的入库流水；发货草稿状态显性提示
