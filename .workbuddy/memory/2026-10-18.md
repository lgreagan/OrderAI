### 17:20 财务「运费/保险代收代付」口径对齐
- 用户疑问：这一栏「向客户收取」在哪录入？只在发货时录过运费保险，不该有差额。
- 事实：「向客户收取」没有独立录入入口，取自 PI 明细里 charge_type=shipping/insurance 的 amount
  （`Generate` 时从 `shipments.freight_cost/insurance_cost` 带入，PI 页面可改金额）；
  「发货实付」取 `shipments.freight_cost/insurance_cost`。当前 700 vs 700，差额 0，与用户判断一致。
- 修掉的不一致：`FinanceRepository.ShipmentCosts` 原来在 SQL 里直接 SUM 原值，而 PI 侧已按
  「CNY ÷ 签发月汇率」折算 → 发货单币种为 CNY 时会出现假差额。
  改为 `ShipmentCharges` 逐单返回 currency/ship_date/原值，在 `FinanceService.convertShipmentCharges`
  里按发货月汇率折成 USD 再汇总；新增 `isCNY`（CNY/RMB/CNH/¥/人民币）供 PI 侧共用。
- 实测：USD 口径 700/700 差 0；CNY 口径 700/104.64 差 595.36 —— 因为库里的旧 PI 是按 USD 存的
  （已存 PI 不会自动重算），折算本身两侧一致（500/6.69=74.74、200/6.69=29.90）。
- `templates/finance.html` 补两句口径说明（录入路径 + 实付按发货月汇率折算）。
- 遗留（未改，等确认）：PI 页面「+ 费用行（保险/运费）」按钮创建的 charge_type 固定为 `other`，
  UI 没有类型下拉；而 `recalcTotals` 与前端 recalc 都只累加 insurance/shipping，
  **手工加的费用行金额不进 PI 合计、也不进代收代付栏**。库里目前没有 other 行。
